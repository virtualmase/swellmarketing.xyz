Do you need special markup for Google AI Search?

Google says no special AI markup, file, or Schema.org type is required for its AI Search features. The useful work is still a clear, crawlable, people-first public record.

Short answer: for Google AI Search features, a site does not need special AI markup, an AI text file, or a dedicated Schema.org type. Google says the same foundational Search practices apply to AI Overviews and AI Mode.[1][2]

That answer is intentionally narrow. It does not mean a public site needs no technical care. It means the first question is not, “What AI tag are we missing?” The first question is whether the page is eligible for ordinary Google Search, can be found and understood, and presents visible information truthfully.

It also does not settle what another platform, crawler, agent, or tool might support. An llms.txt file, API description, or machine-readable feed can have a separate interoperability purpose. The mistake is presenting any of those artifacts as a Google AI Search requirement or a promise of discovery.

Start with the actual baseline

Google says a page must be indexed and eligible to appear in Google Search with a snippet before it can be eligible as a supporting link in AI Overviews or AI Mode.[1] That is a baseline, not a promise. Google also states that meeting requirements and best practices does not guarantee crawling, indexing, or serving.[1]

Structured data still matters, just not for the reason people claim

It would be wrong to turn Google’s “no special AI schema” statement into “structured data does not matter.” Google’s structured-data guidance supports relevant formats for applicable rich-result features and requires markup to be accessible, complete, specific, current, and truthful to the visible page.[3]

Visible-to-structured-data parity

If a statement would be hidden, stale, misleading, or unsupported in the page body, encoding it as JSON-LD does not make the statement safer. Use markup to describe an inspectable page, not to manufacture a result claim.

For a source-led way to review that parity, read The Evidence Contract. For an entity-level review, use Prepare Your Entity Record for AI-Assisted Inspection.

When a separate machine-readable file can be reasonable

A separate file is not automatically a gimmick. It can be useful when a documented downstream system, partner, or internal tool actually consumes it. The responsibility is to name that consumer, state the file’s purpose, maintain the record, and avoid representing it as a Google visibility mechanism.

Google’s current guidance makes the distinction directly: a team may maintain an llms.txt file or similar artifact for another service, but Google Search does not use it to improve visibility in its generative AI features.[2] That is an interoperability decision, not a substitute for an accessible public page.

Keep this separate from a crawler-policy decision. Access, training, and user-initiated fetches are different questions from markup. See AI Access Decisions for the boundary.

Replace the shortcut with a bounded review

Observe

Name the page and the system

Identify the page class, its owner, visible claim, canonical URL, and the documented platform behavior that actually matters.

Prove

Compare visible facts with technical declarations

Check access, internal links, primary text, structured data, and current source records. Name discrepancies without assuming they explain a ranking or answer.

Decide

Repair the first verified constraint

Fix an inaccessible page, unsupported declaration, contradictory description, or missing internal route before commissioning a speculative new file.

Learn

Use the relevant reporting surface

Observe attributable changes through the documented platform and your own analytics. A single appearance, referral, or answer is not causal proof.

Sources and limits

This guide is a Swell interpretation of current Google Search documentation. It does not promise inclusion in AI Overviews, AI Mode, classic results, rich results, other search engines, chat products, or agent systems. It does not say that a separate machine-readable file is useless everywhere, only that Google’s current guidance says it is not required or used to improve visibility in Google Search’s generative AI features.[2]
