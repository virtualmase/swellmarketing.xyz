Short answer: A machine-readable page starts as a readable page. Give the reader the answer, show the relevant evidence, explain why the image is there, write a precise page description, and assign someone to keep the record current. Only then should a machine-readable declaration repeat what the reader can already inspect.

The internet does not need another stream of generated pages trying to occupy every possible phrasing of a question. A reader with a real decision needs the opposite: one clear page that says what is current, why it can be believed, what the visual is meant to show, and what remains outside the page’s control.

This is a shared Swell/ARM operating position. We make content machine-readable for people who do not know where their public record breaks. It is not a promise about what any search engine, social platform, AI system, or browser agent will display. It is a standard for the public record we can actually govern.

The public explanation stack

A useful page is not a pile of separate “SEO elements.” It is one explanation seen through several surfaces. The point is agreement. A reader should not find a different offer in the caption, schema, image, metadata, or call to action than they find in the sentence that carries the claim.

Operating definition

Direct answer → visible claim → source or method → relevant image and caption → accurate metadata → matching declaration → named owner and review date → stated limitation.

SurfaceWhat a person should be able to inspectWhat it should not be used to imply
Direct answerA current, plain-language answer to the page’s question.That a concise sentence is true without support.
Visible claim and sourceThe relevant source, method, date, and material qualifier.That a source applies beyond its stated scope.
Image and captionWhy the image belongs on this page and what information it adds.That an attractive visual is evidence of a commercial result.
MetadataA specific title and description that summarize the actual page.That a site can set a permanent search snippet or social preview.
Machine-readable declarationA truthful structured description of visible page content.That valid markup guarantees inclusion in a rich result or AI answer.
Review controlWho keeps the material statement current and when it was checked.External endorsement or a timeless fact.

Google’s structured-data guidelines make the technical side of this straightforward: markup must represent the page’s visible main content, and correctly implemented markup does not guarantee a search-result appearance.[1] That is not a disappointment. It is the reason the human-facing explanation comes first.

An image has an evidence role

An image earns its place when it helps a reader understand a subject, a process, a before-and-after condition that is truthfully documented, or the source being discussed. A generic stock scene, a synthetic proof image, or a decorative dashboard does not become useful because it has an alt attribute. It needs a real role in the explanation.

Google’s image guidance distinguishes the information carried by an image from the surrounding page context. It recommends standard HTML image elements, relevant nearby text, descriptive filenames, and useful alt text-not keyword stuffing.[2] That gives five distinct surfaces with five distinct jobs.

Image surfaceUse it forAvoid
Image fileA relevant, representative visual on a page that explains it.Generic imagery used as a stand-in for proof.
FilenameA short description of the image subject, such as `public-explanation-stack.png`.Opaque names such as `image-01.png` or a string of keywords.
Alt textThe essential visual information a reader would miss when the image is unavailable.Repeating “image of,” copying the caption, or adding unrelated search terms.
CaptionWhy the image matters to this particular claim or source.Restating the title without adding context.
Surrounding copyThe claim, source, method, and limitation that let the image be interpreted responsibly.Leaving a visually impressive asset to make an unsupported argument alone.

Caption rule

A caption should name what the reader is seeing, identify the source or author where relevant, and state why the visual belongs beside this paragraph. It is not a place to hide a keyword list or make a result claim.

For a practical external discussion of this distinction, Google Search Relations’ “Let’s talk image SEO” episode is a useful companion. The speakers discuss alt text in context, surrounding explanation, descriptive filenames, and why generic imagery is a weak substitute for specific information. It is linked here rather than embedded because the audio discussion-not a decorative player frame-is the relevant material.

Metadata is a description, not a lever

A title and meta description should help a prospective reader decide whether the page answers their question. They are not a backstage control panel for a result page. Google says snippets are generated automatically from page content and may use a meta description when it better describes the page; different queries can produce different snippets.[3]

That is why this guide’s description says exactly what the guide covers: visible explanation, relevant images, captions, metadata, citations, and review ownership. It does not promise that the description will appear verbatim, and it does not turn phrases like “AI visibility” into a claim that a platform will show the page.

The same rule applies to `og:image` and structured image references. If a page specifies one, it should be genuinely relevant to the page, crawlable, and a truthful representative image-not a logo, an extreme crop, or an image with the whole article headline baked into it.[2] [1]

External media is useful when it earns a place

Link to a podcast, video, company profile, public registry, listing, or independent example when it allows a reader to verify a bounded fact or understand a specific practice. Label the role. A primary source supports a factual premise. An identity reference helps disambiguate an organization. An independent example illustrates a practice. None of these links, by themselves, establish quality, affiliation, or a commercial result.

This is radical transparency in the useful sense: show the source role and the limitation rather than surround a reader with named entities as borrowed authority. The same restraint applies to competitors. A competitor reference belongs only when it demonstrates a specific public strength fairly, with no invented comparison and no implied relationship.

The one-page test

  1. Name the decision. Write the reader’s question in ordinary language.
  2. State the current answer. Put the material answer in visible copy and retain the qualifier.
  3. Attach the support. Link the primary source, method note, or publication record needed to inspect the claim.
  4. Give every image a role. Write a descriptive filename, alt text, caption, and surrounding explanation that agree.
  5. Describe the actual page. Write the title and description as a page-specific summary, not a keyword ledger.
  6. Repeat only what is visible. Add structured declarations only when they match the page a reader can inspect.
  7. Assign the review. Name an accountable owner, show a meaningful date, and state what the page does not establish.

If the answer is uncertain at any point, the next action is not more publishing. It is more inspection. Use the Representation Readiness Map to create a private list of conditions to check, or read the Evidence Contract for the visible-claim-to-declaration sequence.
